## Routes and file contract (react-router-dom v7; install it)
Scaffold owns: src/main.tsx, src/App.tsx (routes + auth gate + layout), src/lib/* (supabase.ts with bucket constants REFS_BUCKET='refs', GENS_BUCKET='gens', FINALS_BUCKET='finals'; database.types.ts; api.ts typed wrappers for every RPC above; useProfile hook; useRealtimeTable hook; stage.ts with STAGES order, labels, colours, isAutomated(stage), ageLabel(stage_entered_at)), src/components/Header.tsx (nav: Board, Completed, Clients, Settings (lead only), queue indicator, paused banner, sign out), src/components/Login.tsx (rename to DM Studio).
Route → page component (default export) → file:
- /login → Login (public)
- /brief/:token → BriefFormPage → src/pages/BriefFormPage.tsx (public, no auth, no Header)
- / and /board → BoardPage → src/pages/BoardPage.tsx
- /card/:id → CardPage → src/pages/CardPage.tsx (+ src/components/card/*)
- /completed → CompletedPage → src/pages/CompletedPage.tsx
- /clients → ClientsPage → src/pages/ClientsPage.tsx ; /clients/:id/style → StyleCardPage → src/pages/StyleCardPage.tsx (+ src/components/style/*)
- /settings → SettingsPage → src/pages/SettingsPage.tsx (lead only; others see "Lead only")
Builders edit ONLY their own page files and component folders; they never edit App.tsx, main.tsx or src/lib/*. If a builder needs a helper, it creates it inside its own folder.

## Page requirements
BoardPage: one column per stage in SOP order (intake, review, approved, generating, needs_review, editing, finishing, delivered) plus waiting and failed at the far right; horizontal scroll on narrow screens. Tile: client name, thumbnail (signed URL of current generation image_path, else first reference), first print_text line, stage badge, "in <stage> for <age>" from stage_entered_at (amber after 4 min in automated stages approved/generating/editing/finishing), last_error snippet on failed. Filters: client select, stage multi-toggle, "mine" (approved_by = me). Live via Realtime on cards + generations and a 20 s poll fallback. Header queue indicator: counts of generations queued/working and fin_jobs queued/working vs settings caps; Paused banner when settings.pipeline_paused.
CardPage: two columns. Left: client + form link, every brief field editable (brief_text, print_text lines with role select headline|sub|tagline, garment_color, placement select, due_on, avoid_notes, similarity_tier 1–5) with Save (plain update; disabled while stage generating/editing/finishing); three references with signed URLs and the reference_analysis JSON rendered as key/value; Style Card panel: current locked version for the client (green) or red "No locked Style Card" with link to /clients/:id/style. Right: generations strip (all rows for the card, newest first; kind badge, QC pass/fail, "make current" → set_current_generation), large preview of current generation with previous/current blink toggle, QC report rendered from qc_report JSON (array or object of checks: show pass/fail + note; tolerate unknown shapes), structured magic prompt editor (magic_prompt_json sections as editable text areas, used by Regenerate), action bar: Approve (stage review; confirm dialog showing settings.per_card_price_usd; disabled if no locked Style Card or paused), Accept (stage needs_review → accept_generation), Edit text (dialog: old text prefilled from print_text lines, new text, instruction → request_edit kind edit_text), Edit region (draw a rectangle on the 1024-space preview via canvas; export a black/white mask PNG same size as the image; upload to gens `<card_id>/<generation_id>-mask.png`; instruction → request_edit kind edit_region with mask_path), Regenerate (dialog: rejection_reason select + note + the edited magic prompt → request_edit kind regenerate), Park (move_card waiting with note) / Resume, Retry (stage failed → retry_card), Duplicate (duplicate_card → navigate to new card), lead-only link to the n8n execution. Show last_error prominently on failed.
BriefFormPage: resolve token via start_brief on load (invalid → "This link has expired" screen). Fields per SOP 5.1: 3 image slots (png/jpg/webp, ≤ 15 MB, warn under 512 px short side), description ≤ 400 chars with counter, multi-line exact text (each line one element; optional), garment colour select from the client's garment_colors + "other", product/placement select (front_chest, full_front, back, pocket, tote, mug), optional deadline. On submit: upload the three files to refs/<client_id>/<card_id>/1..3.<ext> with supabase.storage (anon, no session), then submit_brief; show a confirmation screen with the card id; handle the 15-minute grant expiry (offer "start again"). Mobile-first layout.
CompletedPage: delivered cards; card with final badge (metrics px/dpi from fin_jobs), hover shows the generation image, Download (signed URL of finals path), Download all / selected as zip (jszip), Delete selected (remove finals + gens + refs objects for the card, then delete the card row). Reuse DM Finisher's CompletedPanel/download code.
ClientsPage: table of clients (name, active, cards count, locked Style Card version or none, form link with copy button `${origin}/brief/${form_token}`); lead can add/edit a client (name, garment_colors, target_px_w/h, default_similarity_tier, active) and rotate the form token (update form_token to a fresh 32-hex string). StyleCardPage: versions list (version, status, locked_at, note); current locked version highlighted; "New version" (new_style_card_version copies current); editing a draft: form over the Style Card schema (medium, linework {weight, style}, shading, texture, palette [{name, hex, weight}], composition, typography {vibe, placement}, background, mood[], forbid[], garment_colors[]) with a raw JSON panel kept in sync; Save draft (update json); Lock (lock_style_card with note; confirm dialog "locked versions cannot be edited").
SettingsPage (lead): pipeline_paused toggle, per_card_price_usd, max_active_generations, max_active_finish (update settings id=1); prompt templates list grouped by slug with Activate (set active=false on the current active of that slug, then active=true + activated_by/at on the chosen) and "New version" (textarea body, version = max+1, inactive).

## Quality bar
- `npx tsc --noEmit -p tsconfig.app.json` clean, `npm run lint` clean, `npm run build` succeeds.
- No `any` except at JSON boundaries; tolerate null/unknown JSON shapes.
- Every mutation shows a toast on success and error; errors from RPCs display the Postgres message.
- Keyboard focus visible; works at 400 px width (board scrolls horizontally).

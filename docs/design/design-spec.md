## 1. Principles (5)
1. Chrome is calm and achromatic; the artwork supplies the colour. Violet appears on exactly the stage's one primary button, the focus ring, the brand mark and selected/drag states; stage colour lives in 6 px dots and low-saturation badge pairs, never in column backgrounds or panel borders.
2. Three-tier surfaces and text, one token set for both themes: canvas / surface-1 / surface-2 / surface-3 and fg-1 / fg-2 / fg-3 as CSS variables; hover is one ladder step, depth is a hairline in dark and a level-0 shadow in light.
3. Type is tiered, not big: 13 px/500 chrome, 14 px body, 11–12 px meta in tabular figures; Bricolage Grotesque only at 18 px and above (h1 24, wordmark 15); weights capped at 600; sentence case everywhere.
4. Motion means work is happening, and it lives inside the thing being worked on: one signature per long wait (DEVELOP / INSPECT / FINISH), one landing gesture (SETTLE + one ring pulse), 200 ms ease-out entrances, 150 ms exits, nothing animates on 100×/day interactions, reduced motion keeps fades and drops loops.
5. Facts before prose and one obvious next step: price and time on the control before the click, a mono spec row on results, one primary per screen, empty states that are the call to action.

## 7. Accessibility
Contrast (computed): body/meta text ≥ 4.5:1 on every permitted surface (fg-1 17.4/15.1, fg-2 7.2/6.5 — 6.2 on light surface-2, 5.4 on dark surface-3; fg-3 5.22/4.55 light, 5.05/4.61 dark; fg-3 banned on surface-3); white on brand 6.93 light / 5.42 dark, on brand-hover 8.86 / 4.93; brand text 8.86 / 7.45; badge pairs 6.5–8.8; feedback text 5.3–10.8; placeholders 3.2/3.5 (placeholders only); focus ring 5.42 on white, 5.07 on dark canvas; stage dots ≥ 3.7:1 (non-text) and always paired with a text label; image chips white on ≥ 8.7:1. The develop line (2.3:1 on the light checker) is decorative, never the only signal — the chip and live region carry the state.
Focus: one rule for buttons/links/tiles/chips/segments — `focus-ring` = 2 px ring-ring with 2 px offset on focus-visible only; inputs focus (mouse or keyboard) with border ring + 3 px tint, invalid with bad; danger buttons use the same brand ring; the three current ring colours retired. Native checkbox/radio via accent-color.
Keyboard: existing behaviour kept (Dialog trap/Escape/return-focus, PlatformPicker arrows, wizard focus-to-h2, EditTextForm autofocus, two-click arms, EditRegionDialog pixel inputs); Enter submits Generate/Regenerate dialogs; hover-revealed actions (gallery tiles, strip tiles, row actions) are also revealed on focus-within; kbd hints in titles ('Accept · finish  A', 'Fix an area  F', 'Try again  R') are display only until a palette exists (no ⌘K in this scope); no cursor:pointer on tiles/rows.
Live regions: one role=status per card (the existing rail line) announcing phase changes only ('Drawing the design', 'Judging the design', 'Design ready to review', 'Finishing, removing the background'); FrameState and counters aria-hidden; LoadingBar role=progressbar with aria-label + aria-valuetext in words (never a percent); failed banners keep role=alert; toasts keep aria-live polite / role=alert for errors.
Icons and labels: every icon-only button has title === aria-label; icon buttons in rows show a text label at md+; sentence case everywhere; stage colour never conveyed by hue alone (dot + label + badge text).
Touch/phone: chips ≥ 28 px, rows 44 px, inputs 16 px below 640 px, dialogs as bottom sheets, image-chip pill 'Edit text' always visible on touch (no hover), no horizontal page scroll except the board lanes.
Reduced motion: as §6; `prefersReducedMotion()` kept for the scan phase; nothing conveys state by motion alone (every animated state has a chip/badge/text twin).

## 0. Product decisions (2026-09-24)
- Style memory = per-client **Style Card** (locked, versioned JSON) drafted by vision analysis of the client's **reference library**
  (5–15 past designs uploaded once on the client panel) and edited/locked by a designer. Selecting a client anywhere means
  "use this client's locked Style Card". Card references describe that design's subject/inspiration only.
- Engine = Kie.ai **GPT Image 2.5 Sunburst**, image-to-image, model `gpt-image-2-5-sunburst-image-to-image`.
  References are BOTH read by vision into the prompt AND attached as `input_urls` (signed URLs), labelled per similarity tier.
- Designers can create a card from the board with a client dropdown (`create_card_as_designer`). The board is client-scoped:
  a client selector in the header filters everything to that client (its own panel); "All clients" shows everything.
- Each client panel has: form link (copy / rotate), reference library uploader, Style Card status + editor link,
  "Draft Style Card from library" button, New card button.

## 2. Style Card JSON schema (the contract every prompt is built from)
Schema 2 (migration studio_21, 2026-09-30) is ADDITIVE: the 14 schema 1 keys keep their types and every new key may be absent on an older card. A card is drafted by the two-pass profiler (prompt_templates style_sheet v1 = one fixed-vocabulary sheet per library image, then style_profiler v3 = the card, brief first), checked and auto-fixed by Edge Function style-card-check (shared pure module supabase/functions/_shared/style_card_rules.ts, also used by prompt-engine at render time and by the editor) before it is stored, and rendered by prompt-engine render.ts renderStyleCard. This key list is identical to the reference row prompt_templates style_card_render v2 and to docs/sop.html 7.1.
```
schema: 2
medium: string (<=12 words)
realism: iconic|stylised|detailed|realistic
linework: { weight: none|hairline|fine|medium|bold|heavy, style: string (<=12 words), outline: none|thin|thick|keyline }
shading: string (<=12 words)            shading_method: none|flat|hatching|stipple|halftone|cel|painterly
texture: string (<=12 words)            edge_finish: clean|rough|distressed|stamped
palette: [{ name, hex: #RRGGBB, weight: dominant|secondary|accent|outline, role: line|fill|text|disc|accent|highlight, images: [n], snapped_from?: hex }]  (3..8, exactly one dominant, listed first)
palette_variants: [{ garment: dark|light|any, hexes: [hex], images: [n] }]  (optional)
composition: string (<=40 words, no subject nouns)      hero: { framing: chest_up|full_figure|head_only|scene|object|none, scale: small|medium|large|fills }
typography: { vibe, placement, case: UPPER|lower|Title|Mixed|'', headline: { family: FAMILY, weight: light|regular|bold|black, effects: [arched|inline_hatching|outline|banner|drop_line|distressed] }, secondary: { family, weight, effects } }
  FAMILY = slab_serif|display_serif|condensed_sans|grotesk_sans|script|brush|blackletter|woodtype|stencil|hand_lettered|other
background: 'flat mid-grey #808080, isolated artwork'   mood: [string]
subjects: [string]        subject_sources: { '<subject>': brief|images|both }
brand_text: { items: [{ text, role: handle|est|tagline|brand, placement }], always_present: boolean }   (NEVER rendered into the prompt, never sent to QC as forbid)
forbid: [string (<=10 words)] (2..8)   signature_moves: [string (<=10 words)]   garment_colors: [string]
representative_images: [n, n, n]       field_evidence: { '<path>': { images: [n], contradicts: [n], agreement?: 0..1 } }
brief_check: { must_have_seen: [], must_have_not_seen: [], avoid_seen_in: ['IMAGE n: ...'] }
evidence: ['IMAGE n: note'] (5..15)    rules: { palette_mode, text_case, lock_typography, lock_composition }   reference_ids: [uuid]   source: 'library'
validation: { errors: [], warnings: [], fixes: [], checked_at }
```
Rendered into the CLIENT STYLE CARD block (in this order, one "- " line each, no trailing periods): medium, realism + edge_finish, linework, shading_method + shading, texture, palette (STRICT or FLEXIBLE from rules.palette_mode; the palette_variants entry matching the garment side when present), composition (LOCKED or GUIDE from rules.lock_composition), hero, typography (LOCKED or GUIDE from rules.lock_typography; rendered once, the QUOTE header only points at it), background, mood, signature_moves, and last the NEGATIVE line built from forbid. NOT rendered: subjects (the SUBJECT block names the one hero and lists the pool as supporting elements only), garment_colors (the BRIEF block states the garment once), brand_text, subject_sources, representative_images, field_evidence, brief_check, evidence, validation, reference_ids, source, rules, schema.
The vision profiler returns exactly this shape (JSON mode); style-card-check blocks storing and locking on validation.errors (palette count, hex, one dominant, empty medium/typography, evidence out of range, rule words or text demands inside style fields, a brief subject missing, wrong background). Designers edit and lock; the pipeline refuses to generate without a locked card (a draft may be used only for the hidden onboarding test render, and the prompt then labels it "(draft)").

## 3. Edge Functions (Deno, pure, unit-tested with fixtures; verify_jwt off; they check x-studio-secret by calling rpc studio_secret_ok with the header forwarded)
### prompt-engine  POST {generation_id}
Loads: generation (kind, brief_snapshot, style_card_snapshot + the style_cards row status for the header, magic_prompt_json for regenerate/edit, parent), card (reference_analysis, reference_roles, print_text, garment_color, placement, avoid_notes, similarity_tier, client_submission.subject), client (default tier, style_brief.niche, garment_colors), active design_lessons (client then global), approved exemplars for the client (final_prompt of delivered cards, newest; v8 keeps only the Description line + the quoted text lines, <= 160 chars, de-duplicated by description, max 3), active prompt_templates rows (slugs: print_rules, tier_rules, text_rules, defects, render_order).
Builds magic_prompt_json (v8, prompt-engine v8 2026-09-30; render.ts is the source of truth, buildMagicPrompt is pure and golden-tested) with keys in this order and renders rendered_prompt from it:
  1 print_rules (template; the renderer appends the PRECEDENCE line "exact text > print rules > SUBJECT > Style Card > similarity policy > reference descriptions > brief prose" as its last line)
  2 style_card {version, status locked|draft, lines[], negatives, prose = lines joined, rules} - the card passes through the shared checkStyleCard FIXES first (no '..', 'Locked:' or 'as_typed' from old drafts), then one "- " line per key in the style_card_render v2 order (Medium, Rendering, Linework, Shading, Texture, Palette STRICT|FLEXIBLE with the palette_variants entry for the garment side, Composition LOCKED|GUIDE, Hero framing, Typography LOCKED|GUIDE rendered ONCE, Background, Mood, Signature moves, NEGATIVE last); subjects, garment_colors, brand_text and evidence keys are never rendered here
  3 lessons 4 exemplars
  5 reference_reading (flat compat keys + references[] per slot + same_design when WF-1 stored analysis_prompt v3): per-slot block "REFERENCES - each attached image has ONE job" (Image i WHAT TO MAKE / ART STYLE applied WITHIN the Style Card / LETTERING letterforms only, "Not attached: ... - the Style Card governs", text seen never reproduced) or, for legacy flat analyses, today's block made tier-aware (tier <= 2 art style + mood-only palette; tier 3 adds "Hero concept to remix"; tier >= 4 the full block)
  6 similarity_tier (1–5 text from template; {{niche}} and the v1 bare NICHE are filled from clients.style_brief.niche, else "this client's usual subject matter")
  6b subject {text, source brief|reference|style_card|description, pool, slot?}: explicit brief_snapshot.subject / client_submission.subject > the WHAT TO MAKE slot's hero at tier >= 3 > Style Card subjects[0] > "as described in the BRIEF Description"; rendered as the SUBJECT block (the on-design text is LETTERING ONLY and never chooses the subject) after the similarity policy and before BRIEF
  7 brief (description, garment colour - stated only here -, placement, avoid notes) 8 text (exact-text block: each line verbatim, once; the QUOTE header says "lettering only - the words never change the SUBJECT above; set in the Style Card Typography line above" - or, when the card typography is a GUIDE and a LETTERING slot is attached, "in the lettering of the LETTERING reference (Image k), within the Style Card typography"; if no text: "no text anywhere")
R3: renderPrompt still accepts the pre-v8 shape (style_card.prose only, no subject) because edit kinds inherit the parent's magic_prompt_json; on that path the Style Card block, the typography pointer and a missing subject are refreshed from the same (linted) snapshot.
Also returns: aspect_ratio from placement (docs/kie-gpt-image-2-5.md table), resolution from settings, input_paths plan: which reference paths to attach (card refs always, role per slot from cards.reference_roles - subject_reference / style_reference (slot_role art_style) / typography_reference, null = legacy style_reference; up to 3 client_look library refs when tier ≥ 3, preferring the card's representative_images, never excluded ones, never a path already attached) and the per-image role labels rendered into the prompt (one per roled slot: "Image 1: WHAT TO MAKE - ...", "Image 2: ART STYLE - ...", "Image 3: LETTERING - ..."; legacy runs keep "Image 1–3: style/subject references for this design; Image 4–6: examples of the client's established look — match the look, never copy a subject").
Writes magic_prompt_json, rendered_prompt, final_prompt (= rendered_prompt unless a polish node changes it), aspect_ratio, resolution, model, vendor, platform, reference_urls onto the generation row, and returns them plus style_card_status and subject. Fails 422 with a clear message when the client has no locked Style Card, the card has no reference_analysis, or the rendered prompt still contains an unresolved template token ({{...}} or the bare word NICHE).
Tests: `npm run test:functions` (supabase/functions/_test/run.mjs, a Node shim for Deno.test) runs prompt-engine/render_test.ts (golden fixtures/chicken_v2.json = the live 006b5ba1 snapshot with fixtures/chicken_v2.expected.txt, fixtures/e2e_v4.json), qc-judge/qc_test.ts and style-card-check/check_test.ts; the template assertions read the v2 bodies from the studio_21 migration text.

### qc-judge  POST {generation_id, qc_raw, exact_text_lines?, style_card?, expected_subject?, attempt?}
Normalises the vision QC response into qc_report v2 {verdict pass|warn|fail|unverified, checks:[{id, name, pass, note}] (the 9 core checks + not_cropped + style_palette + text_height), score, style_match {score, checks:[{id palette|medium|typography|composition|subject|forbid, field, pass, note}], subject_seen, case_seen} from the qc_prompt v2 "style" key (a missing key = pass null "not reported", never a failure; composition always passes when rules.lock_composition is false; forbid_hits numbers become "forbidden element present: <forbid[n-1]>" - the v1 regex matcher over issues is gone), needs_regen, corrective_instruction, style_violations[], text_ok, min_text_height_frac}. Verdict: 'fail' only on core checks; 'warn' when every core check passes and style_match.score < 100, the compat palette check fails or the judge said pass:false with zero failed checks. needs_regen = a failed regen-worthy core check, or (settings.qc_subject_regen, default true) an expected subject (magic_prompt_json.subject.text, else brief_snapshot.subject, else cards.client_submission.subject) with style.subject_ok false - then the corrective instruction (what WF-2 appends) ends with "Draw <subject> as the hero, not <subject_seen>; the text is lettering only and never chooses the subject". Writes qc_report/needs_regen/text_elements; returns them plus verdict and style_match. Never throws on malformed JSON (returns needs_regen false with a parse_error note and flags for the designer).
